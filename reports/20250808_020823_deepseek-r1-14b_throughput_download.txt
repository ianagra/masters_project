# QoS Assessment Report: Throughput Download Approach

## 1. Executive Summary
This report presents a comprehensive analysis of Quality of Service (QoS) issues detected through network probes in a Brazilian ISP's environment. The study identifies two clusters of intervals based on statistical change-point detection and multivariate characterization, revealing distinct risk profiles associated with throughput download performance. Cluster 0 is characterized by high-risk, unstable behavior, while Cluster 1 represents low-risk, stable connections. Key findings include the identification of critical clients (client02, client07) and servers (rnp_rj, rnp_sp) strongly associated with instability. The report provides actionable insights for addressing network performance degradation.

## 2. Detailed Findings

### Cluster Analysis
- **Cluster 1**: Stable behavior with long intervals (mean duration: 24.29 days), low event frequency (0.078), and superior throughput (~632 Mbps download, ~684 Mbps upload) and RTT (~16 ms download, ~18 ms upload).
- **Cluster 0**: Unstable behavior with short intervals (mean duration: 10.64 days), high event frequency (0.738), and degraded throughput (~452 Mbps download, ~492 Mbps upload) and RTT (~59 ms download, ~60 ms upload).

### Critical Element Identification
- **Client02**: Strong association with Cluster 0 (coefficient: -1.952).
- **Client07**: Pronounced association with Cluster 0 (coefficient: -1.734).
- **rnp_rj**: Significant link to instability (coefficient: -1.368).
- **rnp_sp**: Tendency towards instability (coefficient: -1.233).

### Individual Diagnoses
#### Client02:
- Exhibited stable performance (~578-600 Mbps throughput, ~9.3 ms RTT) except during mid-June and early July when it shifted to Cluster 1.
- Key interaction with rnp_rj suggests potential routing inefficiencies.

#### Client07:
- Showed notable variability, with most intervals involving rnp_rj.
- Download throughput fluctuated significantly (800-900 Mbps stable vs. 522 Mbps drop), and RTT varied between ~14 ms and higher values during interactions with rnp_rj.

#### rnp_rj:
- Majority of intervals in Cluster 1, but significant instability (~25%) observed.
- Recurring issues with clients like client1 and client16 indicate potential network inefficiencies.

#### rnp_sp:
- Shifted from stable to unstable behavior over time (75% in Cluster 1).
- Consistent high RTT during interactions with rnp_rj suggests routing issues.

## 3. Recommended Actions
- **Execute Traceroute**: From rnp_rj and rnp_sp to frequently problematic clients (client02, client07) to identify bottlenecks.
- **Monitor Network Traffic**: Use tools like iftop or nethogs during peak periods to detect congestion.
- **Investigate Routing Issues**: Reconfigure routes or implement alternative paths based on traceroute findings.
- **Upgrade Infrastructure**: Consider hardware/software upgrades for servers with persistent performance issues (rnp_rj, rnp_sp).
- **Implement Proactive Monitoring**: Set up alerts for high RTT and throughput drops to enable timely interventions.

This report provides a structured approach to addressing QoS issues, focusing on critical elements and actionable steps to enhance network stability.
